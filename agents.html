When we will not build you an AI agent

If your data is not modeled, an agent will give answers that sound confident and are wrong. It will not say "I don't know", it will guess how two tables join and present the result in a convincing sentence. Anyone selling you an agent on unorganized data is selling you a new problem, one that is harder to spot than the one you already have.

So in many cases our answer is to build the foundation first and talk about an agent later. It is less impressive, and it is what works.

What an agent on company data actually does

A user asks a question in plain language. The agent translates it into a query against the data warehouse, runs it, and returns the answer together with its source: which table, which time window, and which metric definition was used. That is the difference between a tool you can rely on and a chat that sounds clever. An answer without a source is an opinion.

What has to exist before you start

  • A data warehouse. One place where the data sits stably, not a live query against your operational systems.
  • Agreed metric definitions. If "revenue" is calculated differently in marketing and finance, the agent will pick one and not tell you.
  • A semantic layer. An explicit description of tables, relationships and metrics, so the agent does not have to guess.
  • Permissions. Who is allowed to see what. An agent that skips this turns every question into a potential data leak.

Where it breaks

Three failure points recur. Ambiguous definitions: a question like "how many active customers do we have" is meaningless until someone decides what active means. Wrong joins: when the model guesses how two tables connect, the result looks plausible and the error is invisible in the number itself. Permissions: a user asks an innocent question and receives a figure they were never meant to see.

All three are solved in the same place, and it is not the choice of model: it is the data layer underneath the agent.

How answers are kept correct

  • Grounded in definitions. The agent uses the metrics defined in the model rather than inventing its own calculation.
  • Cited sources. Every answer states where it came from, so it can be checked.
  • An evaluation set. A collection of questions with known answers that runs after every change, to catch regressions.
  • Clear boundaries. Questions the agent should not answer come back as "I don't have that", not as a guess.

Security and access

The work happens inside your own cloud, with read-only access limited to defined schemas. Raw data stays in your environment, and user permissions are enforced at the query level, not at the level of how the question was phrased.
